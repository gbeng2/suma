# payments rules

This page covers money inside suma: member balances ("ledgers"), saved cards and bank accounts ("payment methods"), money coming in ("funding transactions"), money going out and refunds ("payout transactions"), manual ledger moves ("book transactions"), subsidy automations ("payment triggers"), and the charge records attached to orders and trips. It lists the rules the software enforces, what you or a member will see when a rule is hit, and where to fix it in the admin app. Every rule below was taken from the code at the file and line shown. "No admin fix - needs engineer" means the code shows no admin screen or button for it.

Words used on this page: the "cash ledger" is a member's general balance. The "platform account" is suma's own account; every member transaction has the platform on the other side. A "system setting" is a value engineers set for the whole installation; staff cannot change it in admin.

### Refunds

| Rule (plain English) | Symptom staff would see | Fix in admin | Severity (error/warning/info) | file:line |
|---|---|---|---|---|
